# Архитектура и что оптимизировать дальше

Короткий разбор, где реально лежит профит и куда вкладывать усилия. Отсортировано
по влиянию на дельту, а не по порядку в коде.

## 1. Отправка (Astralane) — сделано, но это НЕ главный рычаг

Реализовано (`src/relay.rs`):
- **Вход** (`submit_primary`) идёт на ОДИН эндпоинт (первый в `[[relays]]`), ровно
  один раз — иначе две копии с разными tip обе исполнятся → двойная покупка.
- **Выход** (`broadcast_build`) веерится на ВСЕ эндпоинты, у каждого свой tip;
  приземляется одна (durable nonce + Lighthouse-гейт идемпотентны).
- Astralane: `sendTransaction`, ключ в URL, tip отдельной инструкцией на `astra…`
  (relay добавляет сам, рандомит аккаунт), опц. `mevProtect`.

Важно: Astralane — это **сендер, а не data-RPC**. Чтение состояния (баланс
reward-кошелька, новые монеты) оставляем на быстром RPC. Задержка ЧТЕНИЯ для входа
важна не меньше задержки отправки.

### tip-экономика
Tip в Astralane — инструкция в той же tx. Если gated-sell падает на ассерте —
падает и tip, платится только базовая комиссия (~5000 lamports). Значит на ВЫХОДЕ
можно типовать агрессивно: платишь tip только за приземлившуюся попытку. На ВХОДЕ
tip платится один раз.

### mev-protect
- **Выход**: `mev_protect=true` имеет смысл — дамп неликвидного мемкоина легко
  сэндвичат, защита бережёт цену выхода.
- **Вход**: защита от фронтрана при заходе в снапшот. Тюним по факту.

### регион
Ставить гейтвей рядом с read-нодой и лидерами: для EU — Frankfurt/Amsterdam
(их рекомендация — слать на edge + ближайший регион одновременно).

## 2. Триггер входа (ОРАКУЛ) — здесь главный профит

Мы зарабатываем тем, что попадаем в снапшот раунда. Источник сигнала выбран —
**Raiden Pulse (шреды)**, `src/shreds.rs`: декодированные транзакции из шредов по
gRPC, ДО блока. Фильтр по reward-кошельку OTC `2k5hrzuy…` + pump-программе. Самый
ранний сигнал, какой вообще есть (раньше, чем Yellowstone/gRPC по подтверждённым
слотам). Сейчас поток только логируется (`feebot shreds` тейлит его); **следующий
шаг — завести вход прямо от шред-событий** вместо опроса `/api/coins`.

Два неизвестных определяют EV:

1. **Когда именно сработает раунд.** `/api/coins` НЕ отдаёт накопленный pending-SOL
   (есть только `snapshot.{marketCap,holders,liquidity,volume24h}`). По шредам видим
   раунд в момент его транзакции на reward-кошельке — это и есть триггер выхода, а
   запуски новых монет и их прогрев — триггер входа.
2. **Наша доля раздачи** = наш вес / весь «квалифицированный флоат» (кошельки ≥ $20)
   на момент снапшота. Конкуренты (два кошелька из ANALYSIS.md) делят тот же пирог.
   Больше buy → больше доля, но и больше просадка монеты и больше флоат →
   убывающая отдача. Есть оптимальный размер входа на монету.

## 2b. Отправка — три сендера, выбор по бенчу

`src/relay.rs` знает Astralane, Nozomi, Constant-K (staked, без tip) и Jito. Вход —
на один эндпоинт (без двойной покупки), выход — веер со своим tip у каждого.
`feebot bench` замеряет land-latency по всем релеям твоим ключом — так и решим,
что быстрее (Nozomi vs Astralane vs Constant-K), без гаданий. Tip на выходе почти
бесплатен: падает на гейте — падает и tip.

## 3. Безопасный веер входа — Lighthouse «ATA пуст»

Сейчас вход — один эндпоинт (безопасно, но не параллельно). Чтобы веерить и вход
(быстрее попасть в снапшот), нужен ассерт «мой токен-аккаунт ещё не существует /
lamports == 0» первой инструкцией — тогда из N копий исполнится одна. У конкурента
в buy-tx такой ассерт есть; надо снять точные байты инструкции Lighthouse
`AssertAccountInfo (lamports)` и добавить в `src/lighthouse.rs` (сейчас там только
`AssertTokenAccount Amount`).

## 4. Durable nonce на выход

Включить `strategy.nonce_account`. Подписываем выход один раз, спамим сколько угодно;
упавшие на гейте попытки nonce не тратят. Ровно схема разобранного бота. Без nonce
переподписываем каждые ~60 c под новый blockhash.

## 5. Фильтры (дельта на отборе) — `src/filters.rs`

Подключить к фактическим полям `snapshot` (капа/холдеры/ликвидность/объём) и
достроить модель EV с учётом конкурентного флоата. Отсекать: слишком большую капу
(не лоукап), мёртвую ликвидность (не продать награду/монету), слишком большой флоат
(наша доля мелкая). `expected_ev_sol` уже есть каркасом.

## Порядок работ (по убыванию отдачи)
1. Фильтры → `snapshot.{marketCap,holders,liquidity,volume24h}` + EV с конкурентами.
2. Durable nonce на выход.
3. Lighthouse «ATA пуст» → безопасный веерный вход.
4. `feebot bench` с боевого VPS → зафиксировать самый быстрый сендер первым.
5. Shred-driven ВХОД по сути раунда: детект накопления/запусков из шред-потока
   (сейчас шреды будят опрос борды; прямого «accrual»-триггера ещё нет).

## Безопасность входа/выхода (по итогам ревью, сделано)
- **Открываем ATA reward-стока на входе** (Token-2022, createIdempotent) — иначе раунд
  нас пропускает и доля уходит другим (бэкфилла нет). Это было дырой.
- **Гейт выхода на НАШ ATA стока** (а не на общий ATA reward-кошелька): «нам начислили»
  — корректный сигнал, что раунд нас зачёл. Убирает ложный триггер от чужих раундов.
- **Не держим два мемкоина на один сток** (общий ATA → ложный триггер).
- **Durable nonce = sign-once**: читаем nonce один раз, подписываем по разу на эндпоинт,
  дальше гоняем кэш без переподписи и RPC. Проверяем authority == payer.
- **Hard-error, если вход не подтвердился** (не спамим пустой выход, не жжём nonce).
- Релей возвращает по ПЕРВОМУ успешному ответу (не ждём медленные).
- ETF/корзины пока пропускаем (ротация стока ломала бы гейт).

## Быстрая транзакция (почему так)
- Вход — один эндпоинт, один раз; выход — кэш подписанных tx, спам до приземления,
  триггер из шредов. CU-лимиты по факту +запас (buy 120k / sell 90k), priority мал
  (основной рычаг — tip релея). ALT не нужен: tx ~20-24 аккаунта, влезает в лимит.

## On-chain флоат и гейт входа (цель 23.10, сделано командой агентов)
- **`src/holders.rs`**: реальный квалифицированный флоат (USD) — топ-держатели через
  `getTokenLargestAccounts` (минус кривая/creator-vault, порог $20); точный путь
  `qualified_float_usd_full` (getProgramAccounts) для приватной ноды. Вшит в EV:
  `float_override` считается в `strategy::float_override` только для прошедших
  `prescreen`, EV берёт реальный флоат, иначе откат на `qualified_float_pct`.
- **Гейт входа** (`lighthouse::assert_account_lamports`/`assert_owner_system`,
  disc 0x05, сверено с клиентом Lighthouse 2.0.0 + живые байты): первой инструкцией
  «мой ATA монеты пуст» (нет аккаунта → lamports==0; пустой → amount==0). Из N
  веерных копий покупает ровно одна. `entry_gate=true`, `fanout_entry` опц.
- **OTC round-accrual он-чейн НЕ читается** (per-round леджеры, не предраундовый
  счётчик). Прокси близости = баланс pump creator-vault; можно добавить как
  `AssertAccountInfo::Lamports`-гейт на вход (не реализовано, опц.).

## Блокер №1 ПОДТВЕРЖДЁН (23.10, декод живых tx бота)
OTC-монеты — **Token-2022** минты. Вход реально идёт инструкцией **`buy_exact_sol_in`**
(disc 38fc74089edfcd5f, 18 аккаунтов), выход — **`sell`** (disc 33e685a4…, 16 аккаунтов).
Точные шаблоны (порядок аккаунтов, флаги, data) — в `src/pumpfun.rs` (блок «ЖИВАЯ
СПЕКА»). Текущие классические `build_buy`/`build_sell` под обычный SPL — **для этих
монет НЕ сработают**. Надёжный способ без тестов: строить по шаблону реальной tx
монеты (копировать coin-аккаунты, подменять свои 5,6,13 / 5,6) + ATA под Token-2022.
Это затрагивает вход/выход/гейт/инсинератор (везде ATA монеты = Token-2022) — делать
и проверять микродепозитом (0.1–0.3 SOL) в ТЕСТ-ФАЗЕ, не слать вслепую.

## Снапшот своп vs раздача — проверять эмпирически в тесте
Из скрина пользователя и истории reward-кошелька: раунд = отдельная tx свопа
(SOL→сток) и затем ~через 3 блока отдельные tx раздачи стока держателям. Рабочесть
«влезть в гэп» зависит от момента заморозки снапшота. Косвенно: разобранный бот
держал 34с–10мин (не ~600ms гэп) → вероятно снапшот у свопа/раньше. Дешевле всего
проверить в тесте: купить монету в гэпе микро-суммой и посмотреть, зачли ли наградой.
